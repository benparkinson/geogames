# Geo data pipeline

Standalone `main` programs, not part of the Spring app, turn the raw sources in `geodata/` (repo root, **not** in the jar) into `src/main/resources/processed/`. The raw and processed files are large: hidden from ripgrep by `.ignore`, and read only with a narrow `head -c` or `grep -o`.

## Sources

- `geodata/countries/`: `countries.geo.json` (Natural Earth, never edited), `officialNames.json` (Natural Earth name → the name the games use: the current official short name, with the UN's short form as the reference; the old name automatically stays an alias unless it differs only in accents or punctuation), `additionalNames.json` (aliases, keyed by the name the games use) and `excludedNames.json` (non-country features such as bases and reefs to skip, by Natural Earth name). A key in any of them that matches nothing fails the loader. `continents.json` (hand-written, keyed by the game's country name, as in `processed/country-shapes`) gives each country one or two of the six continents: Africa, Asia, Europe, North America, South America, Oceania (the same names the river and lake data use; "Australia" is only the country). It follows the UN geoscheme, with Central America and the Caribbean in North America and territories placed where they lie, and exactly Russia, Türkiye, Kazakhstan, Azerbaijan, Georgia and Egypt have two. `CountryShapeMain` fails when a shape has no entry, a key matches no shape, or a value is empty, has more than two entries or names another continent.
- `geodata/rivers/`: `naturalearth/ne_10m_rivers_lake_centerlines_scale_rank.geojson` (Natural Earth, public domain; the plain `lake_centerlines` file has no Wikidata IDs, this one does; it is the only source of river geometry), `wikidata.json` (Wikidata labels, aliases, sitelinks and continents per QID, committed) and `overrides.json` (hand-written, keyed by QID: `exclude`, `name`, `continent`, `aliases`, `addAliases`, `removeAliases`, `mainPieceOnly` (drop lines detached from the river's main piece, for a far-off stretch Natural Earth tags with the same QID, such as the Congo's upper Lualaba), `reverseFlow`, `source`, `mouth`). Overrides only correct data and can't supply geometry: rivers are ranked by Wikipedia sitelinks whether or not they have an override, and the top of each continent is taken up to `RIVER_QUOTAS` in `RiverLoaderMain`.
- `geodata/lakes/`: `naturalearth/ne_10m_lakes.geojson` (Natural Earth, public domain; the plain file, not the `_europe` / `_north_america` / `_historic` / `_pluvial` variants), `wikidata.json` (from `WikidataMain`, committed) and `overrides.json` (hand-written, keyed by QID: `exclude`, `name`, `continent`, `aliases`, `addAliases`, `removeAliases`, `countries`; `countries` replaces the located countries outright). Lakes are ranked by Wikipedia sitelinks, with the top of each continent taken up to `LAKE_QUOTAS` in `LakeLoaderMain`.

- `geodata/cities/`: `naturalearth/ne_10m_populated_places_simple.geojson` (Natural Earth, public domain, 4.9 MB), downloaded once from `https://raw.githubusercontent.com/nvkelso/natural-earth-vector/v5.1.2/geojson/ne_10m_populated_places_simple.geojson` (the release tag, not `master`). Nothing in the build or the tests fetches it. Properties used: `name`, `pop_max`, `adm0name`, `adm0cap`, `featurecla`; the position is the geometry. Natural Earth is already credited in the footer.
- `geodata/relief/`: `NE2_HR_LC_SR_W_DR.zip` (Natural Earth II with shaded relief, water and drainages, high resolution, 325,795,333 bytes), downloaded on 2026-11-17 from `https://naciscdn.org/naturalearth/10m/raster/NE2_HR_LC_SR_W_DR.zip`, SHA-256 `e4a6e27c121cab119835ac38f17695768011d12a2a7d9e57d5cddf65566fcec0`, and unzipped there (a 21,600 × 10,800 GeoTIFF in plain longitude/latitude). Public domain. **Git-ignored** (the TIFF is 700 MB) and not in CI, so nothing in the build or the tests fetches it.

## Programs

- `countries/CountryLoaderMain <countries.geo.json> <officialNames.json> <additionalNames.json> <excludedNames.json> <outDir>` clears `*.json` in `outDir`, then writes `processed/countries/*.json` (one `Country` per file, the file name in plain ASCII).
- `countries/CountryShapeMain <processedCountriesDir> <continents.json> <outDir>` reads `processed/countries` and writes `processed/country-shapes/*.json` (one `CountryShape` per country, Antarctica left out): `continents` (from `continents.json`), simplified `outline`, `coast` and `landBorders` lines, `neighbours` (each with the indexes of its lines in `landBorders`), `areaKm2` (the largest part, from the full-resolution rings) and a `focus` box. Coast and borders come from which edges two countries share (`CountryShapeBuilder`; shared borders are simplified identically on both sides so no gaps open). **Editing `officialNames.json`, `additionalNames.json`, `excludedNames.json` or `continents.json` means re-running `CountryLoaderMain` and then `CountryShapeMain`**, or `ProcessedDataIT` fails. A rename also reaches the rivers, lakes, cities and country rivers, so run the whole `regenerate-data` profile, update any key in `CAPITAL_OVERRIDES` and rewrite the name in `processed/tripoints.json` by hand (that file needs the network to regenerate).
- `tripoint/TripointLoaderMain <processedCountriesDir> <outFile>` scrapes Wikipedia's list of tripoints and writes the single file `processed/tripoints.json`, an array of `{coordinate, countryNames}`. Each Wikipedia coordinate is snapped by `TripointSnapper` to the vertex where the three countries' borders meet; a tripoint with no such vertex within 30 km is dropped. The tripoint count comes from the file, so there's nothing to update by hand.
- `features/WikidataMain <naturalEarth.geojson> <outFile wikidata.json>` fetches the Wikidata facts for every QID in a Natural Earth file. **It is the only feature program that uses the network.** Run it once and commit `wikidata.json`. `loaders/features` is shared by every Natural Earth + Wikidata feature type (reader, Wikidata fetch, continents, aliases, fame-ranked selection with continent quotas, simplification, country location); `loaders/rivers` holds only what is about rivers. `loaders/features` also has the small shared helpers: `GeoPoints` (4-decimal rounding, `roundLine` drops repeated points, `toPositions`), `GeoJsonCoordinates` (a geometry node to lists of points) and `Geo.ANTARCTICA`. Lake geometry deliberately keeps repeated points, so it uses `round4` only. `CountryShapeBuilder` is split into `CountryRings` (reading and keys), `BorderRuns` (edge labels and runs) and `SharedLineSimplifier`; `CountryRiversMain` into `CountryRiverLimits`, `CountryLakes` and `CountryRiversSummary`.
- `rivers/RiverLoaderMain <naturalEarth.geojson> <wikidata.json> <overrides.json> <countriesDir> <outDir>` is offline and deterministic. It works out each river's `source` and `mouth` (`RiverEnds`: the two points furthest apart along the joined lines, with the flow direction voted from how the lines were digitised; `reverseFlow` or explicit `source`/`mouth` overrides fix the rivers it gets wrong) and the `countries` it flows through (`CountryLocator`, from `processed/countries`). It clears `*.json` in `outDir`, simplifies the geometry (Douglas-Peucker, at most 600 points per river) and writes `processed/rivers/<slug>-<QID>.json`, one `River` per file. It prints a summary, including famous rivers skipped for lack of a continent. Editing `overrides.json` means re-running this (no need to refetch Wikidata).
- `lakes/LakeLoaderMain <naturalEarth.geojson> <wikidata.json> <overrides.json> <countriesDir> <outDir>` is offline and deterministic. It assembles lake candidates (`LakeAssembler`: at least 100 km² unless an override names the lake; `LakeGeometry` simplifies to at most 800 points, dropping islands under 1% of their lake and fragments under 2% of the main body), picks the top of each continent, locates the countries on the shore (`CountryLocator.locateRings`, at least 5 km), clears `*.json` in `outDir` and writes `processed/lakes/<slug>-<QID>.json`, one `Lake` per file. It prints a summary including famous lakes skipped for lack of a continent and lakes with no countries. Editing `overrides.json` means re-running this (no need to refetch Wikidata).

- `cities/CityLoaderMain <populatedPlaces.geojson> <countriesDir> <outFile>` is offline and deterministic. It gives each Natural Earth populated place the country whose polygon holds it (`CountryLocator.countryAt`); a coastal city just outside is looked for 0.03° north, south, east and west, and then matched by its `adm0name`; otherwise it is dropped (Antarctica's research stations, which have no shape, always are). It keeps each country's 40 largest cities by `pop_max` and every capital, and writes the single file `processed/cities.json`: an array of `{country, cities: [{name, lon, lat, population, capital}]}`, countries sorted by name, cities by population then name, coordinates to 4 decimals. A place is a capital when `adm0cap` is 1 or its `featurecla` is "Admin-0 capital" (Natural Earth misses a few, such as Juba); a country with none gets its largest "Admin-0 region capital" (Greenland's Nuuk). The summary lists the eligible countries (the threshold is in `CountryCitiesEligibility`).
- `rivers/CountryRiversMain <rivers.geojson> <wikidata.json> <overrides.json> <lakes.geojson> <countriesDir> <outDir>` reads **every** feature of the Natural Earth rivers file (not the 50 famous rivers of `RiverLoaderMain`), cuts each line at the country borders (`RiverClipper`: a segment belongs to every country that its midpoint, or the points 0.03° north, south, east and west of it, is in, so a river along a border goes to both), simplifies each stretch with `CountryShapeBuilder.tolerance` (the same tolerance as the country's outline) and drops stretches under 5 km. A country keeps at most 4,000 river points (the least important rivers are dropped first) and at most 2,000 lake points (the smallest lakes are dropped first). Rivers with a `scalerank` up to 4 (about a quarter of the length) are `major`, the rest `minor`. Lakes are every lake of at least 100 km² in `ne_10m_lakes.geojson`, simplified with `LakeGeometry`, given whole to every country with at least 5 km of shore. It clears `*.json` in `outDir` and writes one file per country that has a stretch of river (named as `CountryWriter` names country files) and `index.json` (name, file, river count, km, lake count). Each country file also has `longestRiver`, the name of its longest named river (`CountryLongestRiver`), or null. The names come from `RiverAssembler` run over the whole rivers file (every river with a Wikidata ID, at least 200 km and a name, with the same names, aliases and overrides as the river games, about 985 rivers), **without** `RiverLoaderMain`'s `FeatureSelector` and `RIVER_QUOTAS`: that 50-river limit stays in `RiverLoaderMain`, because `RiverLoaderService.loadRivers()` caches every river file with its geometry. The clipper keeps each stretch's Wikidata ID (`Run.qid`); a country's stretches are summed per river before simplifying, a river with under 50 km in the country is ignored, and one whose name or alias contains the country's name or alias as a whole word, or whose name is part of the country's (the Niger for Niger, the Congo for either Congo), is never named, so the next longest is taken. **The app reads one country's file each time a round is built and never keeps it, so the large geometry is never on the heap** (see `CountryRiversService`); keep the files small if this program changes, and run `scripts/measure-heap.sh`.
- `relief/ReliefTilesMain <source.tif> <outDir> <maxZoom>` cuts the Natural Earth II raster into Web Mercator JPEG tiles (256 px, quality 0.85) `outDir/{z}/{x}/{y}.jpg` for zooms 0..maxZoom, each rendered straight from the source (`ReliefTiler`), deterministically. It deletes `outDir` first and refuses a folder not named `relief`. The tiles are committed under `client/public/tiles/relief/` (zooms 0–6, 5,461 tiles, 36.7 MB; the source resolution stops being finer at zoom 6) and served by the site itself. Run it with `-Xmx4g`: `java -Xmx4g -cp target/classes com.parkinson.benjamin.geogames.loaders.relief.ReliefTilesMain geodata/relief/NE2_HR_LC_SR_W_DR.tif client/public/tiles/relief 6` (after `./mvnw -q -DskipTests -Dskip.frontend compile`; about 3.5 minutes). It is **not** part of `regenerate-data` or `check-processed-data.sh`, because the source is not in the repo.

## Checking the data is current

`bash scripts/check-processed-data.sh` (needs `JAVA_HOME`; the CI `data` job runs it) runs the `regenerate-data` Maven profile, which re-runs `CountryLoaderMain`, `CountryShapeMain`, `RiverLoaderMain`, `LakeLoaderMain`, `CountryRiversMain` and `CityLoaderMain` into `target/regen/`, then diffs each output directory (and `cities.json`) against `src/main/resources/processed/`. It fails and lists the files when `geodata/` or a loader changed and the processed data was not regenerated. It skips `TripointLoaderMain` and `WikidataMain` because they use the network. `.gitattributes` keeps every text file LF, so the diff is exact on every OS.

A new data source needs a credit in the home page footer (see `client/CLAUDE.md`).
