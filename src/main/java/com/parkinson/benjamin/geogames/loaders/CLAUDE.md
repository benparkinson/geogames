# Geo data pipeline

Standalone `main` programs, not part of the Spring app, turn the raw sources in `geodata/` (repo root, **not** in the jar) into `src/main/resources/processed/`. The raw and processed files are large: hidden from ripgrep by `.ignore`, and read only with a narrow `head -c` or `grep -o`.

## Sources

- `geodata/countries/`: `countries.geo.json` (Natural Earth), `additionalNames.json` (aliases) and `excludedNames.json` (non-country features such as bases and reefs to skip).
- `geodata/rivers/`: `naturalearth/ne_10m_rivers_lake_centerlines_scale_rank.geojson` (Natural Earth, public domain; the plain `lake_centerlines` file has no Wikidata IDs, this one does; it is the only source of river geometry), `wikidata.json` (Wikidata labels, aliases, sitelinks and continents per QID, committed) and `overrides.json` (hand-written, keyed by QID: `exclude`, `name`, `continent`, `aliases`, `addAliases`, `removeAliases`, `mainPieceOnly` (drop lines detached from the river's main piece, for a far-off stretch Natural Earth tags with the same QID, such as the Congo's upper Lualaba), `reverseFlow`, `source`, `mouth`). Overrides only correct data and can't supply geometry: rivers are ranked by Wikipedia sitelinks whether or not they have an override, and the top of each continent is taken up to `RIVER_QUOTAS` in `RiverLoaderMain`.
- `geodata/lakes/`: `naturalearth/ne_10m_lakes.geojson` (Natural Earth, public domain; the plain file, not the `_europe` / `_north_america` / `_historic` / `_pluvial` variants), `wikidata.json` (from `WikidataMain`, committed) and `overrides.json` (hand-written, keyed by QID: `exclude`, `name`, `continent`, `aliases`, `addAliases`, `removeAliases`, `countries`; `countries` replaces the located countries outright). Lakes are ranked by Wikipedia sitelinks, with the top of each continent taken up to `LAKE_QUOTAS` in `LakeLoaderMain`.

## Programs

- `countries/CountryLoaderMain <countries.geo.json> <additionalNames.json> <excludedNames.json> <outDir>` clears `*.json` in `outDir`, then writes `processed/countries/*.json` (one `Country` per file).
- `countries/CountryShapeMain <processedCountriesDir> <outDir>` reads `processed/countries` and writes `processed/country-shapes/*.json` (one `CountryShape` per country, Antarctica left out): simplified `outline`, `coast` and `landBorders` lines, `neighbours` and a `focus` box. Coast and borders come from which edges two countries share (`CountryShapeBuilder`; shared borders are simplified identically on both sides so no gaps open). **Editing `additionalNames.json` or `excludedNames.json` means re-running `CountryLoaderMain` and then `CountryShapeMain`**, or `ProcessedDataIT` fails.
- `tripoint/TripointLoaderMain <processedCountriesDir> <outFile>` scrapes Wikipedia's list of tripoints and writes the single file `processed/tripoints.json`, an array of `{coordinate, countryNames}`. Each Wikipedia coordinate is snapped by `TripointSnapper` to the vertex where the three countries' borders meet; a tripoint with no such vertex within 30 km is dropped. The tripoint count comes from the file, so there's nothing to update by hand.
- `features/WikidataMain <naturalEarth.geojson> <outFile wikidata.json>` fetches the Wikidata facts for every QID in a Natural Earth file. **It is the only feature program that uses the network.** Run it once and commit `wikidata.json`. `loaders/features` is shared by every Natural Earth + Wikidata feature type (reader, Wikidata fetch, continents, aliases, fame-ranked selection with continent quotas, simplification, country location); `loaders/rivers` holds only what is about rivers.
- `rivers/RiverLoaderMain <naturalEarth.geojson> <wikidata.json> <overrides.json> <countriesDir> <outDir>` is offline and deterministic. It works out each river's `source` and `mouth` (`RiverEnds`: the two points furthest apart along the joined lines, with the flow direction voted from how the lines were digitised; `reverseFlow` or explicit `source`/`mouth` overrides fix the rivers it gets wrong) and the `countries` it flows through (`CountryLocator`, from `processed/countries`). It clears `*.json` in `outDir`, simplifies the geometry (Douglas-Peucker, at most 600 points per river) and writes `processed/rivers/<slug>-<QID>.json`, one `River` per file. It prints a summary, including famous rivers skipped for lack of a continent. Editing `overrides.json` means re-running this (no need to refetch Wikidata).
- `lakes/LakeLoaderMain <naturalEarth.geojson> <wikidata.json> <overrides.json> <countriesDir> <outDir>` is offline and deterministic. It assembles lake candidates (`LakeAssembler`: at least 100 km² unless an override names the lake; `LakeGeometry` simplifies to at most 800 points, dropping islands under 1% of their lake and fragments under 2% of the main body), picks the top of each continent, locates the countries on the shore (`CountryLocator.locateRings`, at least 5 km), clears `*.json` in `outDir` and writes `processed/lakes/<slug>-<QID>.json`, one `Lake` per file. It prints a summary including famous lakes skipped for lack of a continent and lakes with no countries. Editing `overrides.json` means re-running this (no need to refetch Wikidata).

## Checking the data is current

`bash scripts/check-processed-data.sh` (needs `JAVA_HOME`; the CI `data` job runs it) runs the `regenerate-data` Maven profile, which re-runs `CountryLoaderMain`, `CountryShapeMain`, `RiverLoaderMain` and `LakeLoaderMain` into `target/regen/`, then diffs each output directory against `src/main/resources/processed/`. It fails and lists the files when `geodata/` or a loader changed and the processed data was not regenerated. It skips `TripointLoaderMain` and `WikidataMain` because they use the network. `.gitattributes` keeps every text file LF, so the diff is exact on every OS.

A new data source needs a credit in the home page footer (see `client/CLAUDE.md`).
