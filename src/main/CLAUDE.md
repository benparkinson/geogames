# src/main: configuration, database, data (`resources/`)

- `resources/processed/` is generated by the offline loaders. Don't edit it by hand: see `src/main/java/com/parkinson/benjamin/geogames/loaders/CLAUDE.md`. Its files are large (some a single line of megabytes), so read them with `head -c` or `grep -o`, never in full.
- `resources/db/migration/` belongs to Flyway (`ddl-auto=validate`). Never edit an applied migration; any entity change needs a new `V<n>__...sql`. The same migrations run on H2 (PostgreSQL mode) in every test.
  `PostgresMigrationIT` also runs them, Hibernate's schema validation and a played game against a real PostgreSQL (Testcontainers, `prod` profile). It needs Docker: without it the test is skipped locally, but never in CI, where a missing Docker fails the build.
- `geogames.cors.allowed-origins` in `application.properties` (comma-separated) is applied to `/api/**` by `config/WebConfig`. Update it if the hosting changes.

## Profiles and the production database

The default profile needs no database or secrets (H2 in memory). The `prod` profile (`application-prod.properties`, turned on in Render with `SPRING_PROFILES_ACTIVE=prod`) reads `DATABASE_URL` (a JDBC URL, `jdbc:postgresql://<host>/<db>?sslmode=require&channelBinding=require`, Neon's direct endpoint, not `-pooler`), `DATABASE_USERNAME` and `DATABASE_PASSWORD`, and fails at start-up naming any that is missing (`ProdDatabaseCheck`). Never set `SPRING_DATASOURCE_*` variables in Render.

**Privacy:** a game stores no user data, `created_at` is rounded down to the hour, and the `prod` profile turns Logbook request logging off (it logs each client address), so a game can't be matched to a person. Keep it that way: don't add exact timestamps, client addresses or request logging to production.

To try it locally against a Postgres: `DATABASE_URL=... DATABASE_USERNAME=... DATABASE_PASSWORD=... java -jar target/geogames-0.0.1-SNAPSHOT.jar --spring.profiles.active=prod`.

Production uses Neon's free plan (1 GB, 100 compute-hours a month, sleeps after 5 minutes idle; reaching the compute limit suspends the database until next month). Move to Render's paid web service plus Render Postgres Basic (about $13 a month) when Neon's compute use is on course for about 70 of the 100 hours, or storage passes 0.5 GB. Slow first loads are the free web service waking up, not the database, so upgrade the web service first. Moving needs no data migration: games are disposable, so change the three variables and Flyway creates the schema.
