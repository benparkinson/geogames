# Frontend (`client/`)

Next.js 16, React 19, TypeScript, TanStack Query, react-bootstrap, react-leaflet. Use the Node that Maven installed (`target/node`, v24) for npm commands: the system Node may be older than Next 16 supports. `bash scripts/check-frontend.sh` (repo root) runs lint, `lint:rules`, `tsc` and Vitest with that Node and prints only a summary.

## Commands

- Dev server with hot reload on port 3000: `npm run dev`. It calls the backend at `http://localhost:8080`.
- Type-check: `npm run typecheck` (`tsc --noEmit`; CI runs it with lint).
- Lint: `npm run lint` (zero warnings allowed). TypeScript is pinned to 6.0 (`~6.0.3`) because typescript-eslint doesn't support TS 7 yet (typescript-eslint#10940); Dependabot ignores major TypeScript bumps. Drop the pin and the `ignore` entry once it does.
- Lint rules check: `npm run lint:rules` lints `lint-probe/probe.tsx`, which breaks one rule from each ESLint plugin, and fails unless every rule in `scripts/check-lint-rules.mjs` fires. This catches a plugin that silently stops reporting after an ESLint upgrade (several declare peer `eslint` ≤ 9). `npm run lint` and `tsc` ignore the probe folder. When adding a plugin, add a violation and its rule id to both files.
- Production static export: `npm run build` runs `next build` (with `output: "export"` in `next.config.mjs`) and writes to `out/`. Before that (and before `npm run dev`) `scripts/third-party-licenses.mjs` writes the licence text of every production npm package to `public/third-party-licenses.txt` (git-ignored), which the home page footer links to: the minified bundle keeps no licence comments, and MIT/BSD/Hippocratic (react-leaflet) licences need the notice to ship with the code.
- Tests (Vitest + React Testing Library + jsdom): `npm test` (single run), `npm run test:watch`, `npm run coverage` (v8; only the `*MapWrapper.tsx` files are excluded).

## Tests

- Tests are colocated with their source as `*.test.ts(x)` under `src`, and shared helpers (fixtures, a `fetch` router, a query-client wrapper) live in `src/test/`. Never put test files under `pages/`, because Next would treat them as routes.
- Test files are type-checked by `next build`, so import `describe`/`it`/`expect`/`vi` from `vitest` explicitly.
- Never render real Leaflet maps. Mock the `*MapWrapper` modules in tests of the games, and test the `*Map.tsx` components themselves with `vi.mock("react-leaflet", async () => await import("../../test/leafletMock"))`, which draws each layer as a `<div>` so a test can check what is shown while playing and after the round (`drawnLayers()`, `drawnTileUrls()`, `drawnMarkers()`).
- Testing Library only detects Jest's fake timers, so with `vi.useFakeTimers()` use `fireEvent` instead of `userEvent`.
- Components use TanStack Query through the provider in `pages/_app.tsx`, so tests wrap them in a `QueryClientProvider` (`renderWithClient` in `src/test/render.tsx`).
- **Contract.** `src/api/contract.test.ts` checks `src/test/fixtures.ts` against `src/test/api-shapes.json` (generated by the backend's `ApiContractIT`, see the root `CLAUDE.md`). When the shapes change, update the fixtures, or list the new backend fields in its `IGNORED_BACKEND_FIELDS` with a reason. The shape format in `src/test/shape.ts` must match `JsonShape.java`.

## Structure (`src/`)

- `api/` owns fetching (`fetchJson`), query keys, hooks and the one `JSON.parse` of `jsonBlob`; components never call `fetch`. `api/gateway.ts` picks the backend URL (see the root `CLAUDE.md`).
- `games/common/` is the game-agnostic shell: round page, summary, `MapGame`, answer matching and the guess reducer.
- Each `games/<name>/` folder holds one game: its module, component, model types and maps.
- `games/registry.ts` is the only list of games.
- `map/` holds the shared Leaflet helpers.
- `useGuessList(kind)` (in `games/common/`) gives the autocomplete and spell check for countries, rivers and lakes; a game whose answers come from a fixed list should use it.
- The `QueryClientProvider` lives in `pages/_app.tsx`.

## Answers

The client checks answers, not the server. It compares guesses with the data in `jsonBlob`, including `additionalNames` aliases normalised by `stringHelper.normaliseString`, and reports only the final `AnswerState` with `hintsUsed` and `wrongGuessCount`. `wrongGuessCount` counts the guesses recorded with `answer === null`, so only those that use up the guess limit: empty, duplicate and unknown guesses and correct guesses don't count. The matching lives in `games/common/answers.ts` (`matchAnswer`) and the guess rules (duplicates, aliases, unknown names, hints) in the pure `guessReducer.ts` next to it. `guessReducer` also enforces `guessLimit` (only wrong guesses count) and can finish a round as `OUT_OF_GUESSES`; `GuessState.gaveUp` means "the answers are revealed" and is true both for giving up and for running out of guesses. Scoring lives in `games/common/scoring.ts` (it must agree with the backend's `model/Scoring`) and needs no per-game code.

## Adding a game

Create `src/games/<name>/` with:
- a module built by `defineGame` (its fields are described in `games/types.ts`: the backend `type`, titles, description, icon, component and `answerNames`),
- a component, usually built on the generic `games/common/MapGame`,
- a `*Map.tsx` + `*MapWrapper.tsx` pair that takes `MapProps<T>`.

Then add the module to `GAME_MODULES` in `games/registry.ts`, whose order is the home page order. Set `extraDifficult: true` on the module to show it in the home page's "Extra difficult" section, after Mixed (River Shapes and Lake Shapes do this). Nothing in `games/common/`, `GameRoundPage`, `GameSummary` or `HomePage` needs to change.

`MapGame` takes `blankMap` (a grey map while playing) and `mapCaption` (text over the map while playing) separately. The component gives `MapGame` its answers as `AnswerCandidate[]` (a name plus aliases), and matching (aliases, duplicates) is handled centrally. The component supplies `hints` content for `round.hintCount` hints (the count comes from the backend `GameType.hintCount`, so the component doesn't set its own), and `MapGame` reports `{answerState, hintsUsed, wrongGuesses}`.

**Leaflet and SSR.** Leaflet can't render on the server. Each map has a `*MapWrapper.tsx` that is just a `dynamic(() => import("./X"), { ssr: false, ... })` call (keep the `import(...)` literally in that file), and the real `*Map.tsx` takes `MapProps<T>` (`data`, `gameOver`, `gaveUp`, `hintsUsed`). Follow this pattern for new maps.

## Game families

- **Rivers** (`games/rivers/`): `RiverGame.tsx`'s `makeRiverGame(config)` builds each variant's component from a map, a prompt, a caption and hints, with shared layers in `RiverLayers.tsx` and hint builders in `riverHints.ts`.
- **Lakes** (`games/lakes/`): the module (`index.ts`), `LakeGame.tsx`, the `LakeShapesMap` pair (the polygon on a blank map with a scale bar, and the satellite map once the round ends: solved, given up or out of guesses), `lakeHints.ts` (continent, countries on the shore, first letter) and `useGuessList("lakes")`.
- **Country shapes** (`games/countries/`): `CountryShapeGame.tsx`'s `makeCountryShapeGame(variant)` builds each component from a map, a prompt, a caption and hints, with shared layers in `CountryLayers.tsx` (`FocusFit` fits the largest part, so Russia, Fiji and overseas territories don't zoom out to the world) and hint builders in `countryHints.ts` plus the generic `games/common/hints.ts`. The games use `useGuessList("countries")` and `isKnownGuess`.
- Removing a variant: delete its module, registry entry and map pair, and the backend constant and bean.
