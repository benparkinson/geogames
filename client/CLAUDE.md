# Frontend (`client/`)

Next.js 16, React 19, TypeScript, TanStack Query, react-leaflet (Bootstrap CSS for layout utilities only; see Theme in the root `CLAUDE.md`). Use the Node that Maven installed (`target/node`, v24) for npm commands: the system Node may be older than Next 16 supports. `bash scripts/check-frontend.sh` (repo root) runs lint, `lint:rules`, `tsc` and Vitest with that Node and prints only a summary.

## Commands

- Dev server with hot reload on port 3000: `npm run dev`. It calls the backend at `http://localhost:8080`.
- Type-check: `npm run typecheck` (`tsc --noEmit`; CI runs it with lint).
- Format: `npm run format` (Prettier, 120 columns; `.prettierrc.json`). Format before committing.
- Lint: `npm run lint` (zero warnings allowed, checks the formatting with `prettier --check`, then `scripts/check-theme.mjs`, which keeps colours in `src/theme/tokens.css`). TypeScript is pinned to 6.0 (`~6.0.3`) because typescript-eslint doesn't support TS 7 yet (typescript-eslint#10940); Dependabot ignores major TypeScript bumps. Drop the pin and the `ignore` entry once it does.
- Lint rules check: `npm run lint:rules` lints `lint-probe/probe.tsx`, which breaks one rule from each ESLint plugin, and fails unless every rule in `scripts/check-lint-rules.mjs` fires. This catches a plugin that silently stops reporting after an ESLint upgrade (several declare peer `eslint` ≤ 9). `npm run lint` and `tsc` ignore the probe folder. When adding a plugin, add a violation and its rule id to both files.
- Production static export: `npm run build` runs `next build` (with `output: "export"` in `next.config.mjs`) and writes to `out/`. Before that (and before `npm run dev`) `scripts/third-party-licenses.mjs` writes the licence text of every production npm package to `public/third-party-licenses.txt` (git-ignored), which the home page footer links to: the minified bundle keeps no licence comments, and MIT/BSD/Hippocratic (react-leaflet) licences need the notice to ship with the code.
- Tests (Vitest + React Testing Library + jsdom): `npm test` (single run), `npm run test:watch`, `npm run coverage` (v8; only the `*MapWrapper.tsx` files are excluded).

## Tests

- Tests are colocated with their source as `*.test.ts(x)` under `src`, and shared helpers (fixtures, a `fetch` router, a query-client wrapper) live in `src/test/`. Never put test files under `pages/`, because Next would treat them as routes.
- Test files are type-checked by `next build`, so import `describe`/`it`/`expect`/`vi` from `vitest` explicitly.
- Never render real Leaflet maps. Mock the `*MapWrapper` modules in tests of the games, and test the `*Map.tsx` components themselves with `vi.mock("react-leaflet", async () => await import("../../test/leafletMock"))`, which draws each layer as a `<div>` so a test can check what is shown while playing and after the round (`drawnLayers()`, `drawnTileUrls()`, `drawnMarkers()`).
- Testing Library only detects Jest's fake timers, so with `vi.useFakeTimers()` use `fireEvent` instead of `userEvent`.
- Components use TanStack Query through the provider in `pages/_app.tsx`, so tests wrap them in a `QueryClientProvider` (`renderWithClient` in `src/test/render.tsx`).
- **Contract.** `src/api/contract.test.ts` checks `src/test/fixtures.ts` against `src/test/api-shapes.json` (generated by the backend's `ApiContractIT`, see the root `CLAUDE.md`). When the shapes change, update the fixtures, or list the new backend fields in its `IGNORED_BACKEND_FIELDS` with a reason. The shape format in `src/test/shape.ts` must match `JsonShape.java`.

## Daily challenge (`src/daily/`)

`/daily` (`pages/daily.tsx`, `daily/DailyPage`) is one puzzle a day, the same five rounds for everyone (backend `CLAUDE.md`, "Daily challenge"). It shows the game itself (`GameRoundPage` with a `daily` prop), so the URL stays `/daily` and a reload works; a shared link must never point at a game id. The page is pre-rendered at build time: **nothing may read the date or localStorage while rendering**. The date comes from `useToday()` and storage from `useDailyEntry()`, both `useSyncExternalStore` with a `null` server snapshot, and the game is created on click (crawlers and link previews fetch the page). The date is the player's local date (`localDateString`, never `toISOString()`).

localStorage key `gg-daily` (`dailyStorage.ts`; it and `settings/hardMode.ts` are both built on `settings/localStore.ts`, which keeps the value in memory when storage is blocked) holds only the latest daily: game id, whether Hard mode stayed on, and the result once finished (so Share works after the server deletes the game). It is a convenience, not enforcement: a private window or another device can replay. It must be listed on the privacy page. `shareText.ts` is spoiler-free (squares, score, `/daily` link).

## Credits

The credits live in `components/SiteFooter` (the home, summary and privacy pages) and `map/MapCredits` (every map, through Leaflet's attribution control). They name Natural Earth (all geometry), Wikidata (names), Wikipedia (the tripoint list, CC BY-SA, positions adjusted) and the Flaticon icon authors. The relief tiles are Natural Earth II (public domain), self-hosted in `public/tiles/relief/` (zooms 0–6, made by `ReliefTilesMain`, committed), so no browser request for a map leaves the site; always draw them with `map/ReliefTiles`, never a bare `TileLayer`. Every map is built on `map/GameMap`, which adds `MapCredits` and `MapResizer` (ESLint rejects a bare `MapContainer`); pass `credit` for a credit only that map needs. A new data source or tile layer needs a credit in the footer. A new data source or third party that receives requests from the browser also needs a line on the privacy page (`components/PrivacyPage`).

## Structure (`src/`)

- `api/` owns fetching (`fetchJson`), query keys, hooks and the one `JSON.parse` of `jsonBlob`; components never call `fetch`. `api/gateway.ts` picks the backend URL (see the root `CLAUDE.md`).
- `games/common/` is the game-agnostic shell: round page, summary, `MapGame` (its panel is `GuessForm`, `RoundActions` and `WrongGuessList`; `useRoundGuesses` holds the round's guesses and hints), answer matching and the guess reducer.
- Each `games/<name>/` folder holds one game: its module, component, model types and maps.
- `games/registry.ts` is the only list of games.
- `map/` holds the shared Leaflet helpers.
- `useGuessList(kind)` (in `games/common/`) gives the autocomplete and spell check for countries, rivers and lakes; a game whose answers come from a fixed list gets it through `PlaceGame`, and game components don't call it themselves.
- The `QueryClientProvider` lives in `pages/_app.tsx`.

## Answers

The client checks answers, not the server. It compares guesses with the data in `jsonBlob`, including `additionalNames` aliases normalised by `stringHelper.normaliseString`, and reports only the final `AnswerState` with `hintsUsed` and `wrongGuessCount`. `wrongGuessCount` counts the guesses recorded with `answer === null`, so only those that use up the guess limit: empty, duplicate and unknown guesses and correct guesses don't count. The matching lives in `games/common/answers.ts` (`matchAnswer`) and the guess rules (duplicates, aliases, unknown names, hints) in the pure `guessReducer.ts` next to it. `guessReducer` also enforces `guessLimit` (only wrong guesses count) and can finish a round as `OUT_OF_GUESSES`; `GuessState.gaveUp` means "the answers are revealed" and is true both for giving up and for running out of guesses. The server keeps the guesses: `useRoundGuesses` (in `MapGame`) calls `round.recordGuess` for every guess the reducer records (before it reports an answer; `useRecordGuess` and `useSubmitAnswer` share a mutation scope, so they reach the server in that order) and rebuilds its state on mount with `restoreGuessState`, which replays `round.guesses` through the reducer (and re-sends an answer that was lost after the last guess). Hints are saved too, as they are taken: `useRoundGuesses` calls `round.recordHint({hint, guessesBefore})` (same mutation scope), and `restoreGuessState` replays the saved hints interleaved with the guesses (`round.hintsTakenAt`), so `foundAtHint` comes out as it was. The server charges at least the hints it saw. Scoring lives in `games/common/scoring.ts` (it must agree with the backend's `model/Scoring`) and needs no per-game code.

**Distance clues.** A wrong guess in a game whose answers are countries and whose map hides the location gets a clue: the distance and compass direction to the nearest answer not yet found (`GuessClue`, `{km, bearing}`). `GuessConfig.clueFor` computes it in the pure reducer and stores it on the `Guess` and in the `wrong` / `outOfGuesses` result. `games/common/useCountryClues` builds `clueFor` from `GET /api/countries`, which carries a `lat`/`lon` per country (the backend's centroid of the largest part); the maths is in `games/common/distance.ts`. A game opts in by setting `hasClues: true` on its module, and nothing else: `GameRoundPage` copies it to `round.hasClues`, `PlaceGame` then passes `useCountryClues(round.hasClues)` to `MapGame` (and the list is only fetched for such a game), and the home page shows the Hard mode switch (beside the round count) only for it and for Mixed. Tripoint (the map shows where the answers are), rivers and lakes (no positions on the client) deliberately have none. Hard mode (`settings/hardMode.ts`, `useHardMode`, key `gg-hardcore` in `localStorage`, switch in `components/HardModeToggle`) only hides the clues in the UI: they are always computed, and scoring and the server don't know about it.

## Adding a game

Create `src/games/<name>/` with:
- a module built by `defineGame` (its fields are described in `games/types.ts`: the backend `type`, titles, description, icon, component and `answerNames`),
- a component built on `games/common/PlaceGame`, which is `MapGame` for answers that come from one of the place lists (countries, rivers, lakes) and adds the autocomplete, the spell check and the clues,
- a `*Map.tsx` + `*MapWrapper.tsx` pair that takes `MapProps<T>`, with the map built on `map/GameMap` (it adds `MapCredits` and `MapResizer`).

A game whose answers are countries and whose map hides the location only sets `hasClues: true` on its module: `PlaceGame` does the rest. Build the hints with `hintsFrom(description, round, ...builders)` from `games/common/hints.ts` (one builder per hint, `mapHint(text)` for a hint that only changes the map, `cluesDescription(count)` for the description of text hints).

Then add the module to `GAME_MODULES` in `games/registry.ts`, whose order is the home page order. Set `extraDifficult: true` on the module to show it in the home page's "Extra difficult" section, after Mixed (River Shapes and Lake Shapes do this). Nothing in `games/common/`, `GameRoundPage`, `GameSummary` or `HomePage` needs to change.

`MapGame` takes `blankMap` (a grey map while playing) and `mapCaption` (text over the map while playing) separately. The component gives `MapGame` its answers as `AnswerCandidate[]` (a name plus aliases), and matching (aliases, duplicates) is handled centrally. The component supplies `hints` (required) content for `round.hintCount` hints (the count comes from the backend `GameType.hintCount`, so the component doesn't set its own), and `MapGame` reports `{answerState, hintsUsed, wrongGuesses}`.

**Leaflet and SSR.** Leaflet can't render on the server. Each map has a `*MapWrapper.tsx` that is just a `dynamic(() => import("./X"), { ssr: false, ... })` call (keep the `import(...)` literally in that file), and the real `*Map.tsx` takes `MapProps<T>` (`data`, `gameOver`, `gaveUp`, `hintsUsed`). Follow this pattern for new maps.

## Game families

- **Rivers** (`games/rivers/`): `RiverGame.tsx`'s `makeRiverGame(config)` builds each variant's component (on `PlaceGame`) from a map, a prompt, a caption and hints, with shared layers in `RiverLayers.tsx` and hint builders in `riverHints.ts` (`textHints` is `hintsFrom` for text hints).
- **Lakes** (`games/lakes/`): the module (`index.ts`), `LakeGame.tsx`, the `LakeShapesMap` pair (the polygon on a blank map with a scale bar, and the relief map once the round ends: solved, given up or out of guesses), `lakeHints.ts` (continent, number of countries on the shore, first letter) and `PlaceGame` for the lake list.
- **Country shapes** (`games/countries/`): `CountryGame.tsx`'s `makeCountryGame(variant)` builds each component from a map, a prompt, a caption and hints, with shared layers in `CountryLayers.tsx` (`FocusFit` fits the largest part, so Russia, Fiji and overseas territories don't zoom out to the world) and hint builders in `countryHints.ts` plus the generic `games/common/hints.ts`. The games use `PlaceGame` with the country list.
- **Country games** (`games/countries/`, continued): `makeCountryGame<T>` is generic over any round with a `country` (`HasCountry`), so Country Cities (`cities.ts`, `CountryCitiesMap`, `CityLayers`: a `CircleMarker` per city sized by `cityRadius`, the capital drawn again by hint 1, names on hover only once the round is over) and Country Rivers (`countryRivers.ts`, `CountryRiversMap`: `RiverLines` for the thin minor and the clue-line major rivers, `LakeFills` for hint 1) reuse `FocusFit`, `HintLines`, `AnswerOutline` and the hint builders in `countryHints.ts`. Pass the round type explicitly to `makeCountryGame<...>` inside `defineGame`: TypeScript can't infer it through there. A country with no coast or no large lakes gets "It has no coastline" / "It has no large lakes" as the hint text, which is itself a clue.
- **Pairs** (`games/pairs/`): `PairGame.tsx`'s `makePairGame(variant)` (the player names both countries, so `answerCount` is 2) for Border Shapes and Merged Countries, with shared layers in `PairLayers.tsx` and hints in `pairHints.ts`. Border Shapes frames the shared border (`borderBounds`) until the first hint, then both countries (`focus`), and shows the border length in the caption from the start. Merged Countries fills both outlines with `mergedShapeOptions()`: an opaque fill and a stroke of the same colour, because two adjacent polygons filled without a stroke show a hairline seam where they meet, which would give the border away.
- Removing a variant: delete its module, registry entry and map pair, and the backend constant and bean.
